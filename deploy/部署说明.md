# 部署说明（Compose / 华为云 ECS + RDS + DCS）

本文是部署执行的唯一入口文档。所有命令都在仓库根 `privnegotiate/` 下执行，除非另行注明。

> **验证状态**：本机没有 Docker，本文描述的镜像构建、服务依赖顺序、Nginx 反代、容器内 alembic、worker 常驻、验收脚本均**未在真实容器中运行验证**，属于按代码与配置静态核对后的设计结论。首次执行后请把结果回填到本文末尾的「首次部署记录」。
>
> 已逐项核对（静态）：`backend/Dockerfile` 的启动命令与工作目录、`app/core/config.py` 的变量名与 `.env` 查找顺序、`app/api/*` 的路由前缀（无 `/api`）、前端 `src/api.ts` 的默认 `BASE=/api`、`alembic/env.py` 读取 `settings.database_url`。

## 1. 链路组成

| 服务 | 作用 | 对外 | 启动条件 |
| --- | --- | --- | --- |
| `web` | Nginx：前端静态产物 + `/api` 反代 | `WEB_PORT`（默认 80） | `api` 健康 |
| `api` | FastAPI（`uvicorn app.main:app`） | 仅容器网络 8000 | `migrate` 成功退出 |
| `worker` | outbox → Redis 投影（`--loop`） | 无 | `migrate` 成功退出 |
| `migrate` | 一次性执行 `alembic upgrade head` | 无 | MySQL 健康 |
| `mysql` | 本地全量编排用，`profiles: [local-db]` | 仅容器网络 | — |
| `redis` | 本地全量编排用，`profiles: [local-db]` | 仅容器网络 | — |

启动顺序：`mysql healthy → migrate 退出码 0 → api + worker → api /healthz 的 db/redis 均为 ok → web`。

两种形态：

- **本地全量**（容器内 MySQL/Redis）：`docker compose --profile local-db up -d --build`
- **云上**（RDS + DCS，不起本地数据库）：`docker compose up -d --build`，`DATABASE_URL`/`REDIS_URL` 指向云服务内网地址。

> `depends_on ... required: false` 与 `profiles` 需要 Docker Compose **v2.20+**。低于该版本会直接解析失败。

## 2. 部署前准备

### 2.1 环境变量

```bash
cd deploy
cp .env.example .env
python3 -c "import secrets; print(secrets.token_urlsafe(48))"   # 生成 INVITE_TOKEN_SECRET
```

必改项：

1. `INVITE_TOKEN_SECRET`：**留空 compose 会拒绝启动 api**。源码 `app/core/config.py` 的默认值是 `dev-only-invite-secret`，不覆盖则邀请令牌可离线伪造。
2. `MYSQL_PASSWORD` / `MYSQL_ROOT_PASSWORD`：本地编排必须改，且 `DATABASE_URL` 里内嵌的密码要与 `MYSQL_PASSWORD` 完全一致。
3. `APP_ENV=prod`：关闭 `/docs`。

`.env` 位置规则：

- **非容器运行**：`config.py` 只读当前目录和上一级目录的 `.env`，所以在 `backend/` 下启动 uvicorn 时，`.env` 要放在 `backend/` 或仓库根。
- **容器运行**：由 compose 的 `env_file` 直接注入进程环境，与文件位置无关；但 compose 的变量插值读的是 `deploy/.env`，所以部署文件就放 `deploy/.env`。

密码里避免 `$`；如果必须用，写成 `$$` 否则会被 compose 当变量展开。

### 2.2 华为云资源（云上形态）

- **RDS for MySQL 8.0**：创建实例后建库建账号，字符集必须是 utf8mb4。

  ```sql
  CREATE DATABASE privnegotiate DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
  CREATE USER 'privnegotiate'@'%' IDENTIFIED BY '<与 .env 一致的密码>';
  GRANT ALL PRIVILEGES ON privnegotiate.* TO 'privnegotiate'@'%';
  FLUSH PRIVILEGES;
  ```

  `alembic upgrade head` 需要建表/改表权限，上面的 `ALL` 覆盖到该库即可。RDS 白名单要加入 **ECS 内网 IP**（不是公网 IP）。
- **DCS for Redis**：记录内网地址与密码，白名单同样加 ECS 内网 IP。`REDIS_URL` 写成 `redis://:<密码>@<内网地址>:6379/0`；无密码则 `redis://<内网地址>:6379/0`。
- **ECS**：安全组只放行 80（或 `WEB_PORT`）与 SSH；**不要**对公网放行 3306/6379，数据库走内网。
- 资源建议：4 vCPU / 8 GB 起步。CP-SAT（ortools）与 MySQL 同时驻留时 2 GB 机器容易 OOM。

### 2.3 校园网多出口 NAT 与 SSH 白名单

实测同一台机器在数分钟内会从以下出口访问公网，且每次连接可能不同：

- `58.19.27.133`
- `183.94.22.133`
- `183.95.73.133`
- `218.106.117.240`

四个地址均属于 `AS4837 CHINA UNICOM China169 Backbone`（联通湖北），是**校园网出口 NAT 池**，不是无线网/手机流量。已用“仅有线以太网、WLAN 断开”复测，仍出现多个出口；再绑定 WLAN 单独复测 10 轮，又出现 `183.94.22.24`、`218.106.117.235`、`58.19.27.24`、`183.95.73.24`。说明有线和无线共用同一组 `/24` 出口池，只是主机位在变，换成无线不能解决问题。城市级 IP 归属库可能给出武汉/绍兴等不同结果，以 ASN 与机构字段为准。

因此 auto-deploy 预检里的 `ssh_cidr_matches_current_ip` 会随连接变化偶发失败，**不能绑定单个 `/32`**。部署期按以下顺序处理：

1. 预检与部署时把 SSH 来源临时设为 `0.0.0.0/0`（auto-deploy 传 `--ssh-cidr 0.0.0.0/0`），只开放 22，80/8080 保持原样。
2. 实例创建后先验证 `ssh -i .auto-deploy/keys/auto-deploy-key-privnegotiate root@<EIP> true`；若失败说明出口又切换，直接重跑部署，不要改代码。
3. 部署与业务验收完成后立即收紧：删除 22 的 `0.0.0.0/0` 规则。按实测出口池，至少收紧为四个 `/24`（`58.19.27.0/24`、`183.94.22.0/24`、`183.95.73.0/24`、`218.106.117.0/24`）；若学校能提供正式出口地址池，以学校为准。日常不保留公网 SSH，维护期再临时放开。
4. 若安全要求不允许 `0.0.0.0/0`，改用华为云 CloudShell/VNC 登录，或临时用一台带固定 EIP 的跳板机执行同一套 compose 命令。

补充：**手机热点可用作部署专用出口**。实测（Xiaomi 14 热点）12 轮 × 2 端点共 24 次请求，出口始终为 `183.92.243.12`（联通湖北），未发生漂移。使用时必须临时让热点成为默认路由——断开有线，或把 WLAN 接口跃点调到低于以太网——否则 WSL 仍会走校园网出口。部署验收完成后恢复原网络设置。

### 2.4 首次云上验收的数据库选择

仓库里有两份 env，用途不同，不能混用：

- 根目录 `.env`：本地开发用，`REDIS_URL` 指向 `127.0.0.1`，`APP_ENV=dev`，不能直接拿去云上。
- `deploy/.env`：编排用，当前 `DATABASE_URL` 指向服务名 `mysql`、`REDIS_URL` 指向 `redis`，对应单机容器方案。

首次验收建议先用 **A. ECS 单机 + compose 内置 MySQL/Redis**，成本最低、变量最少：

```bash
APP_ENV=prod
DATABASE_URL=mysql+pymysql://privnegotiate:<密码>@mysql:3306/privnegotiate?charset=utf8mb4
REDIS_URL=redis://redis:6379/0
COMPOSE_PROFILES=local-db
```

`COMPOSE_PROFILES=local-db` 必须进入运行 `docker compose` 的环境（或仓库根 `.env`），否则 `mysql`/`redis` 两个 profile 服务不会启动，`api` 会连不上数据库。

比赛最终口径再切 **B. ECS + RDS + DCS**：先创建 VPC/ECS，拿到 ECS 内网 IP 后加入 RDS 与 DCS 白名单，再把 `DATABASE_URL`/`REDIS_URL` 换成内网地址。不要在 ECS 尚未创建时先建 RDS/DCS，否则白名单无法填写。

## 3. 部署

### 3.1 本地全量（验证编排用）

```bash
cd deploy
docker compose --profile local-db up -d --build
docker compose ps
bash verify.sh http://127.0.0.1
```

若 80 被占用：`.env` 里改 `WEB_PORT=8080`，验收命令同步改为 `http://127.0.0.1:8080`。

`verify.sh` 需要宿主机有 `python3`（只用标准库）。Windows 宿主请用 WSL 或 Git Bash 执行。

### 3.2 云上（ECS + RDS + DCS）

```bash
cd deploy
# 按 2.2 修改 .env 的 DATABASE_URL / REDIS_URL，然后：
docker compose up -d --build
docker compose ps
bash verify.sh http://<ECS 公网 IP>
```

`migrate` 是短命容器，`docker compose ps` 里显示 `Exited (0)` 是正常结果；显示非 0 就去看 `docker compose logs migrate`。

ECS 上若拉取 Docker Hub 镜像失败（预检实测 `registry-1.docker.io:443` 可能不可达，而 `docker.m.daocloud.io:443` 可用），先配置镜像加速再启动：

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{"registry-mirrors":["https://docker.m.daocloud.io"]}
EOF
sudo systemctl restart docker
```

仍失败时，把 compose 中 `mysql:8.0`、`redis:7` 与各 Dockerfile 的基础镜像替换为可访问的 SWR/镜像站地址，不要反复重试原地址。

## 4. 验收标准

只看到 `/healthz` 返回 `db=ok` **不算部署成功**——它仅执行 `SELECT 1`，表没建也照样 ok。

1. `curl http://<入口>/healthz` → `{"app":"ok","db":"ok","redis":"ok",...}`（经 Nginx 透传）。
2. `bash deploy/verify.sh http://<入口>` → 脚本创建 13 项候选的协商，**HTTP 201**，并能读到公共视图；最后打印「业务验收通过」。
3. 浏览器打开 `http://<入口>/`，能完成创建 → 邀请 → 作答 → 封轮 → 确认的完整流程（前端静态资源与 `/api` 反代同时被验证）。
4. 投影链路：`docker compose logs worker` 出现 `outbox projection {...}`；Redis 中存在 `pn:<id>:public` 与 `pn:<id>:member:<id>` 键。
5. outbox 无积压：

   ```sql
   SELECT status, COUNT(*) FROM outbox GROUP BY status;
   ```

   `pending` 应能随 worker 每 `WORKER_LOOP_INTERVAL_SECONDS` 秒清空；`failed` 不为空时看 `last_error`。

缓存丢失（Redis 被清/过期）后的恢复路径：

```bash
docker compose exec worker python -m app.workers.outbox_projection --rebuild <negotiation_id>
```

## 5. 常见失败点

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `/healthz` 全 ok，但接口 500 / 建协商 400 以外报错 | 没执行迁移，表不存在 | 看 `docker compose logs migrate`；确认 `DATABASE_URL` 指向同一个库后重跑 `docker compose run --rm migrate` |
| `api` 反复重启，日志 `ValidationError: invite_token_secret` 或 compose 报 `INVITE_TOKEN_SECRET 未设置` | `.env` 里密钥为空 | 填入 `secrets.token_urlsafe(48)` 的值，`docker compose up -d` |
| `Access denied for user ...` | `DATABASE_URL` 内嵌密码与 `MYSQL_PASSWORD` 不一致；或 RDS 白名单没加 ECS 内网 IP | 两处改成同一密码；补白名单 |
| `web` 502 `connect() failed (111: Connection refused)` | `api` 还没 healthy，或事件循环被依赖服务拖住 | `docker compose ps` 看 api 健康状态；`docker compose logs api` |
| `web` 根本不启动，compose 报 `dependency failed to start: container api is unhealthy` | `api` 的 `/healthz` 里 `db` 或 `redis` 不为 ok（密码、白名单、安全组） | `docker compose logs api`，按上面两行排查连接串 |
| 刷新 `/join/...` 等子路径 404 | 自建 Nginx 未做 SPA 回落 | 本仓库 `deploy/nginx/default.conf` 已配 `try_files ... /index.html`；换配置时保留该行 |
| 前端请求 `/api/...` 404 | 反代没剥前缀或指向错服务 | `proxy_pass http://api:8000/;` 末尾斜杠不能少；后端路由本身不带 `/api` |
| 上传菜单截图 413 | Nginx `client_max_body_size` 小于 base64 体积 | 已设 12m；同时注意 `MENU_IMAGE_MAX_BYTES`（默认 6MB 原图） |
| 端口占用 `bind: address already in use` | 80 被宿主机 Nginx/其他容器占用 | 改 `WEB_PORT` 或在宿主机停掉占用方 |
| `docker compose up` 报 `service "mysql" ... not enabled` | 用了旧版 Compose，不支持 `required: false` | 升级到 Compose v2.20+ |
| auto-deploy 预检报 `ssh_cidr_matches_current_ip` | 校园网多出口 NAT 切换了出口 IP | 用 `--ssh-cidr 0.0.0.0/0` 重跑，验收后收紧，见 2.3 |
| `alembic` 报 `Unknown character set` 或中文乱码 | RDS 库/表不是 utf8mb4 | 重建库为 `utf8mb4`，连接串保留 `?charset=utf8mb4` |
| 构建阶段 `npm ci` 失败或把宿主机 node_modules 打进镜像 | 构建上下文没排除 `node_modules` | 仓库根 `.dockerignore` 已排除；不要在 `frontend/` 里保留需要联网的私有依赖 |
| `docker compose build` 拉取超时 | 宿主机 `http_proxy` 设置了但未配 `NO_PROXY` | 给 Docker 配 `NO_PROXY=localhost,127.0.0.1,*.myhuaweicloud.com` |
| 云上误带 `--profile local-db` | 会额外启动本地 mysql/redis 但不被使用 | 云上只执行 `docker compose up -d --build` |
| OOM / 容器被 kill | CP-SAT + MySQL 内存不足 | 升配到 8 GB，或把 MySQL 换成 RDS |

## 6. 更新、停止与数据

```bash
cd deploy
docker compose up -d --build      # 只重建变更服务；migrate 会再跑一次 alembic upgrade head（幂等）
docker compose down                # 停止，保留 mysql-data / redis-data 卷
docker compose down -v             # 连数据卷一起删，本地库会清空，云上形态无影响
```

云上形态不落本地卷，数据在 RDS；ECS 只是无状态计算节点，可随时重建。
